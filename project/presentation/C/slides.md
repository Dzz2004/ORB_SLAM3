# C：深度贡献与退化 — 建议 PPT 页

> 状态（2026-11-26 13:15）：实验全部完成并重评（162 次 = 148 ok + 12 init_failed + 2 run_failed），下面的数字来自 `results/C/depth_ablation.csv`，逐次运行见 `depth_ablation_runs.csv`。页码对应 PROJECT_PLAN 2.6 的 10 页结构，C 负责第 2、5、7 页的部分素材。

## 第 2 页 · 问题背景（C 部分）

- **核心结论**：深度给 SLAM 直接提供尺度，但深度相机会成片失效、噪声随距离增大、整帧丢失；本数据里超过 65.5 m 的深度原本就是 0（easy 平均 4.2%、hard 2.6% 的像素）。
- **用图**：`figures/01_depth_mosaic_easy.png`（原始深度与无效像素 / 噪声 / 中断的对比拼图）。
- **讲稿要点**：
  1. RGB-D 直接给出尺度，单目只能靠观测估计。
  2. 真实深度相机三种常见失效：成片无效、测距噪声随距离增大、短时整帧丢失。
  3. 实验以原始数据的无效比例为起点，往上叠加 0–80% 无效像素、1–10% 相对噪声、0.5–2 s 中断、整条无深度。
  4. 研究问题：深度变差时系统怎样退化，会不会自动退回单目惯性。

## 第 5 页 · 仿真平台与评测设置（C 部分）

- **核心结论**：同一序列、同一故障表、同一评测口径，比较 RGB-D、RGB-D+IMU 与 RGB+IMU（IMU_MONOCULAR 无扰动对照），每个设置 3 个种子。
- **用图**：无（表格）。可放实验矩阵表。
- **讲稿要点**：
  1. TartanAir V2 Office/P004，easy 1220 帧（122 s）、hard 817 帧（82 s），10 Hz，640×640，深度 uint16 米 ×1000。
  2. 4 类故障：无效像素 P00/P20/P50/P80，相对噪声 N1–N4（r = 1/2/5/10%），中断 O05/O10/O20（0.5/1/2 s），整条无深度 depth_off；共 162 次运行（2 序列 × 27 设置 × 3 种子，含对照）。
  3. 主指标是每帧在线轨迹按 (map_id, frame_epoch) 分段对齐的 ATE，段数和覆盖率同时报告；final 轨迹 ATE 作副指标，并与是否回环一起给。
  4. 有效帧 = 状态 OK 且跟踪点数 ≥ 1；恢复 = 连续 ≥3 帧有效且对齐误差 ≤0.5 m，未恢复单独计数。

## 第 7 页 · 视觉与深度退化（C 部分，可拆成 2 页）

### 7a · 无效深度与测距噪声

- **核心结论**：easy 上无效像素加到 50% 时两种模式的 ATE 都没变（RGBD 0.094、IMU_RGBD 0.029–0.038）；P80 的表面 ATE 0.026 m 是 98.7 段把 ATE 压低的伪影（final 0.083 m）。噪声 r ≤ 5% 对 IMU_RGBD 没有可分辨影响（0.030–0.034 m），r = 10% 升到 0.058 m（比无扰动高 62%）。
- **用图**：`figures/02_invalid_ratio_easy.png`、`figures/03_noise_easy.png`（每张三个子图：在线 ATE / 覆盖率 / 分段数）；hard 版本放备用页。
- **讲稿要点**：
  1. 横轴是加入的无效像素比例 / 相对噪声 r；第一图在线 ATE，第二图覆盖率，第三图是分段数（实线全部段、虚线参与 ATE 的段），误差棒为 3 个种子的标准差。
  2. 蓝线 RGB-D、橙线 RGB-D+IMU，绿色虚线是不用深度的 RGB+IMU（0.040 m，覆盖率 0.916）。
  3. 无效深度：两条线在 0–50% 区间基本水平；P80 时 RGBD 的 ATE 掉到 0.026，但第三子图显示段数从 16.7 涨到 98.7，对齐覆盖率只剩 0.850 —— ATE 不可比。
  4. 噪声：RGBD 的 ATE 随 r 下降同样是分段伪影（段数 13 → 86）；IMU_RGBD 在 r = 10% 才有真实退化。
  5. 这 81 次运行里有 2 次崩溃，都是纯 RGBD、种子 2（下一页面讲）。

### 7b · 深度中断与整条无深度

- **核心结论**：0.5/1/2 s 整帧深度中断在 easy 上 18/18 次运行的窗口内有效帧比例都是 1.000——中断期间跟踪从未中断，窗口后的恢复时间因此是 0.0 s；整条无深度时 12/12 初始化失败，系统不会退回单目惯性。
- **用图**：`figures/04_outage_easy.png`、`figures/05_status_easy.png`。
- **讲稿要点**：
  1. 上图横轴是中断时长，纵轴是中断窗口 [10 s, 10+时长) 内有效帧（状态 OK 且跟踪点 ≥ 1）的比例，从每次运行的 tracking.csv 逐帧算；1.0 = 深度整帧丢失期间 RGB 一路接住。原来画恢复时间，因全部为 0.0 s、y 轴只剩 ±0.04，看起来像出错，已换成这个比例。
  2. RGBD 整次运行有组均 1–2 次失跟（单次 0–4 次），但逐次核对 tracking.csv：事件起点最早 28.0 s（另有 28.3、63.7、75.7、85.6 s 等），全部在中断窗口之外，不是中断造成的；IMU_RGBD 为 0。
  3. hard：RGBD 窗口内比例 0.83–1.00（O20 种子 0 = 0.50，失跟起于 11.0 s），IMU_RGBD 0.12–0.60，部分失跟起于 10.0/10.4/10.5/10.7 s；但 hard 无扰动基线本身每次就有 IMU_RGBD 148–152 次、RGBD 29–32 次失跟，3 个种子分不开"中断触发"与"基线重置"，只作观察。
  4. O05 RGBD 的 ATE 均值 0.187 ± 0.150 m（种子 1 单次 0.358）反而比 O20（0.115）差，0.5/1/2 s 之间没有单调关系，3 个种子定不了趋势。
  5. depth_off：12 次运行全部 init_failed，覆盖率 0。逐帧看是"每帧建一个空地图、下一帧就丢"（easy RGBD 种子 0：609 帧 OK 全部 0 个跟踪点，交替 609 帧 LOST），初始化永远凑不够关键帧。
  6. 官方 RGB-D+IMU 面对无深度也不回退到单目惯性——实测如此，和"无缝切换"的预期相反。
  7. 2 次崩溃：P20_s2 t=114.2 s、P80_s2 t=111.7 s，exit 134，Sophus SO3::exp NaN；IMU_RGBD 没有崩溃。

### 7c（可选）· 怎么读 ATE：分段数与回环

- **核心结论**：分段越多 ATE 越乐观；惯性回环后 9/11 次运行的 final ATE 被拉到 6–8 m，在线 ATE 不受影响。两者都必须在图/表上标注，否则容易得出"退化让精度变好"的错误结论。
- **用图**：`figures/02_invalid_ratio_easy.png` 的第三个子图；`06_invalid_ratio_hard.png` 备用（hard P80 IMU_RGBD：186.7 段、对齐覆盖率 0.129、ATE 0.020）。
- **讲稿要点**：
  1. 每段单独对齐，短段自身误差天然小，所以段数与 ATE 必须一起给（第三子图的虚线段 = 真正参与 ATE 的段）。
  2. P80 RGBD：98.7 段、对齐覆盖率 0.850、在线 0.026 m，但 final 0.083 m。
  3. 回环：easy 的 IMU 模式有 11 次回环运行（IMU_RGBD 10、IMU_MONOCULAR 1），其中 9 次的 final 被拉到 6.24–8.04 m（另 2 次为 0.040、0.053 m），同一批在线 ATE 0.024–0.046 m；惯性回环矫正把轨迹拉长约 1.37 倍，RGBD 回环没这个问题（final 0.07–0.48 m）。
  4. hard 上 P80 IMU_RGBD 同理：186.7 段里只有 24.7 段参与 ATE（覆盖率 0.129），ATE 0.020 m 不能读作变准。
