### 页面标题

基线面临的传感器退化问题

### 核心问题句

多传感器都接进来了，系统是否就一定稳？当一种或多种观测退化时，如何判断系统还能不能
继续跟踪？

### 页面结构

页面分为三层：

1. 三张传感器卡片：RGB、IMU、Depth。
2. 每张卡片包含优势、典型退化和 A 基线中观察到的现象。
3. 底部因果链：

```text
观测质量下降 / 约束不足
  -> Tracking / IMU 初始化异常
  -> 失跟或 active map reset
  -> 地图不连续，连续指标失效
```

### 口播讲稿

传感器之间确实互补，但互补不等于任何情况下都不会失跟。

RGB 在纹理丰富时提供主要特征和长期位姿约束，但弱纹理、运动模糊、光照变化和动态遮挡
会减少有效匹配。Hard P001 的 RGB 覆盖率只有 50.3%，三个 seed 都没有形成可用于
全窗口连续评测的 ATE。

IMU 提供高频角速度和加速度，可以在视觉短时变差时补充运动信息。不过它依赖初始化，
bias 不准时积分误差会快速累积。Hard 的 RGB+IMU 覆盖率约为 24.7% 到 35.0%，九个
轨迹/seed 组合中只有一个形成可用主轨迹，日志还多次出现 IMU 未初始化和 active map
reset。

Depth 提供公制尺度和近距三维几何，但深度空洞、噪声、无效像素和连续缺失都会削弱约束。
Hard RGB-D+IMU 虽然有 58% 到 68.7% 的逐帧跟踪覆盖率，但九个组合都没有形成可用的
连续主轨迹。这说明“某些帧有输出”不等于“整段轨迹可靠”。

因此 A 部分的作用不是证明某一种传感器一定失效，而是把现象定位清楚。B 会隔离视觉
退化，C 会隔离深度退化，D 验证视觉中断后的 IMU 预测，E 根据这些状态设计质量感知的
降级与恢复策略。

## 可选 Backup：证据如何读

### 页面标题

基线现象：有 tracking 输出，不代表有可靠轨迹

### 页面内容

使用以下三个证据块：

| 观测量 | 容易误读的数 | 更重要的解释 |
|---|---|---|
| 覆盖率 | IMU/Depth 模式仍有 20%–70% 帧有 pose | 剩余帧可能来自短生命周期地图，不能拼成连续轨迹 |
| 主轨迹可用数 | 个别 seed 有 ATE | 必须与 `/3` 有效 seed 数同时报告 |
| 地图 ID | 某些帧 state=OK | map reset 后世界坐标不连续，全窗口 ATE/RPE 不可定义 |

### 口播讲稿

这里需要区分 tracking 覆盖率与连续轨迹可用性。一个系统可能在一部分帧输出有效 pose，
但这些 pose 分属不同地图，不能直接拼成一条轨迹计算 ATE。因此我们同时报告覆盖率和
主轨迹可用 seed 数，并把跨地图情况明确标为 N/A。

## 不建议的讲法

不要直接说：

- “Hard 失败是因为弱纹理。”
- “加入 IMU 后就应该更稳。”
- “Depth 模式覆盖率最高，所以定位最好。”
- “ATE 为 N/A 就是没有运行。”

建议改为：

- “Hard 场景出现了视觉约束不足、IMU 初始化和地图重置的联合现象。”
- “融合模式提高了部分帧的输出可用性，但没有保证整段轨迹连续。”
- “Depth 模式保留了更多 tracking 帧，但未形成可用于连续 ATE 的主轨迹。”
- “N/A 表示指标不可定义或主轨迹不可用，失败 run 和逐帧日志仍被保留。”
