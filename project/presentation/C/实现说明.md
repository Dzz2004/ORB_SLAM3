## 1. 研究问题

（PROJECT_PLAN 第四节 C）

1. 深度给 RGB-D(+IMU) 融合带来了什么：与 RGB+IMU（IMU_MONOCULAR）相比，精度、覆盖率、失跟有何差别。
2. 深度逐步失效时系统如何退化：无效像素比例、测距噪声、整帧中断。
3. 官方 RGB-D+IMU 模式面对大量无效深度、或整条序列没有深度时，是正常运行、初始化失败，还是反复重置。**不假设它会"无缝切换成单目惯性"**，以实测为准。

## 3. 方法与实现

### 3.1 深度退化

`experiments/C_depth_degradation/depth_corrupt.py`，参数在 `configs/C_depth.yaml`（version `C_depth_v2`）。只替换 depth/，RGB 和其余文件软链接到原序列。随机量只由（种子, 故障名, 帧号）决定。

| 故障 | 档位 | 含义 |
|---|---|---|
| `invalid_pixels` | P00 / P20 / P50 / P80 | 在原本有效的像素中随机置 0 的比例 0 / 20 / 50 / 80%，逐像素独立 |
| `depth_noise` | N1 / N2 / N3 / N4 | 相对高斯噪声 σ = r·z，r = 1 / 2 / 5 / 10%，逐像素逐帧独立；加噪后 ≤ 0 的置 0 |
| `outage` | O05 / O10 / O20 | 从 t = 10 s 起整帧深度置 0，持续 0.5 / 1 / 2 s，RGB 保留 |
| `depth_off` | ALL | 整条序列深度全部置 0，RGB 保留，用来检验 RGB-D(+IMU) 能否初始化 |

### 3.2 实验矩阵

`configs/matrix/C_depth.yaml`，共 162 次运行：

- 序列：easy、hard；种子：0、1、2；模式：RGBD、IMU_RGBD。
- 故障 × 档位：4 + 4 + 3 + 1 = 12 档，外加无扰动对照。
- RGB+IMU 对照：IMU_MONOCULAR 只在无扰动序列上跑（`clean_modes`）。
- 干跑矩阵 `configs/matrix/C_smoke.yaml`：hard × {无扰动, P50, N3, O10, depth_off} × 种子 0 × {RGBD, IMU_RGBD}，加一次 IMU_MONOCULAR，共 11 次运行。

### 3.3 评测口径

由 `scripts/evaluate.py` 实现，`scripts/run_matrix.py` 对每次运行调用两次。

- **主指标**：online 轨迹（每帧在线输出）按段对齐。段 = (map_id, frame_epoch) 的最长连续段；map_id 在跟踪重新初始化时加 1，frame_epoch 在同一地图内世界系变化（IMU 初始化、VIBA1/2 等）时加 1。每段单独做 SE(3) Umeyama 对齐（RGBD / IMU 模式都用 SE(3)），总 ATE 把各段误差合在一起，即按帧数加权。少于 3 个位姿的段不对齐、不计入 ATE。
- **段数必须和 ATE 一起报告**：分段越多 ATE 越乐观。表格里同时给 `n_segments`、`aligned_coverage`。
- **副指标**：final 轨迹（ORB-SLAM3 全局优化后保存的轨迹）整体对齐。hard 的 IMU 模式在保存时崩溃（`Map 0 has 0 KFs`，wait_status=139，见 5.2），没有 final 指标。
- **覆盖率** = 有效帧 / 全部帧（有效帧的定义见下文，不等于状态为 OK）。
- **失跟事件**：首次有效之后每一段连续无效帧算一次；首次有效之前计入初始化延迟。IMU 预测帧（RECENTLY_LOST）不算有效。
- **恢复时间**（PROJECT_PLAN 3.2 第 5 条）：从失跟开始（中断实验则从中断结束）到之后第一次出现连续 ≥ 3 帧有效、且按段对齐后位置误差 ≤ 0.5 m 为止；未恢复记为"未恢复"，不记 0，并单独报告未恢复事件数。
  - **口径偏宽松**：新段刚开始时，这一段是按自己对齐的，误差天然偏小，所以 0.5 m 门限对刚重置的段较容易满足。
  - **中断图的替代指标**：恢复时间在 easy 的中断运行里全为 0.0 s（跟踪从未中断），因此 `03_outage` 图改画中断窗口内有效帧比例（定义同"有效帧"，窗口 = `[outage_start_s, outage_end_s)`），恢复时间只在文字里给出。
- **种子**：每个设置 3 个种子，报告均值 ± 标准差，同时给出成功运行数（初始化失败的运行没有 ATE，不计入 ATE 均值）。
- **有效帧**：状态 OK **且**跟踪到的地图点数 ≥ 1（`--min-tracked-points 1`）。ORB-SLAM3 会对 0 个点的空地图报告 OK（整条无深度时每隔一帧出现），这些帧计为 `n_ok_but_empty`，在覆盖率、失跟、恢复和 ATE 配对里都算无效。原始 tracking.csv 不改。
- **每段丢弃首帧**：约 1/5 的 frame_epoch 事件帧仍带着旧世界系的位姿，所以每段先丢弃第 1 帧再对齐（`--drop-segment-first-frames 1`），丢弃数记在 `n_dropped_segment_first`。
- **回环**：ORB-SLAM3 发生回环时，最终轨迹会被惯性回环矫正拉偏（easy 的 P00 IMU_RGBD 三个种子最终 ATE 7.5–8.0 m，在线 ATE 0.03–0.05 m）。final ATE 一律和 `loop_closure` / `n_loop_events` 一起报告。
- **崩溃**：ORB-SLAM3 被信号终止（例如 Sophus `SO3::exp` 得到 NaN 后 abort，exit 134）记为 run_failed，不重跑；崩溃前写入的帧照常评测，汇总表单列 `n_crashed`，与 init_failed 分开，并写明发生的条件和时间点。

## 6. 主要发现

以下数字除非另注，均来自 `results/C/depth_ablation.csv`；逐次运行的细节来自 `results/C/depth_ablation_runs.csv`。

### 6.1 深度对 RGB-D+IMU 的作用，与 RGB+IMU 相比（easy）

- IMU_RGBD：在线 ATE 0.036 ± 0.004 m，覆盖率 0.998（有效帧 1216/1218），12.3 段，失跟 0 次。
- RGB+IMU（IMU_MONOCULAR 无扰动）：ATE 0.040 ± 0.012 m，覆盖率 0.916（1115.7 帧），50 段，失跟 12.7 次，初始化 1.9 s。
- 结论：在这条序列上，深度带来的不是 ATE 的显著下降（两者都在 0.04 m 量级），而是**覆盖率、分段数和初始化**：IMU_RGBD 多保住约 100 帧（8% 的帧）、分段减少到 1/4、失跟归零、初始化从 1.9 s 缩到 0.2 s。不能说深度让精度提高一个量级。
- 不用 IMU 的纯 RGBD：ATE 0.097 ± 0.026 m（是 IMU_RGBD 的 2.7 倍），覆盖率 0.997，失跟 0.7 次。深度给了尺度和短基线，但少了惯性约束，精度明显差一档。

### 6.2 无效深度（easy，P00–P80）

- RGBD：ATE 从 0.097（无扰动）到 0.103（P20）、0.094（P50），没有随比例上升的趋势；覆盖率 0.985–1.000。到 P80，在线 ATE 反而"降到"0.026，但段数从 16.7 涨到 98.7、对齐覆盖率从 0.977 降到 0.850，final ATE 是 0.083（2 个种子）——这是分段重锚定把 ATE 压低，不是变准。
- RGBD 在 P20（种子 2，t = 114.2 s）和 P80（种子 2，t = 111.7 s）各崩溃 1 次（见 6.6）。
- IMU_RGBD：ATE 0.036 → 0.038 → 0.029 → 0.028，覆盖率 0.998 → 0.987；P80 时失跟事件从 0 涨到 7，段数 12.3 → 23。没有崩溃。
- 结论：easy 上把 80% 的有效深度像素置零，两种模式都还在运行，没有稳定的失效拐点；区别在失败方式——纯 RGBD 靠频繁重初始化维持，最后两次直接崩掉；IMU_RGBD 靠惯性把帧接住，代价是段数和失跟上升。

### 6.3 深度噪声（easy，r = 1–10%）

- RGBD：ATE 0.095（N1）、0.088（N2）、0.067（N3）、0.045（N4），同时段数 13.3 / 17.0 / 31.3 / 86.0，对齐覆盖率 0.981 / 0.970 / 0.933 / 0.822，覆盖率 0.996 → 0.921，失跟 0.3 → 5.0。ATE 的"改善"同样是分段伪影；N4 的 final ATE 0.166 与在线 0.045 差 3.7 倍。
- IMU_RGBD：ATE 0.030 / 0.032 / 0.034 / 0.058，N4 比无扰动（0.036）高 62%，也是唯一一档标准差之外的明显变化；覆盖率保持 ≈0.995（N4 为 0.9945），失跟 0 → 2.3，段数 12 → 25。
- 结论：r ≤ 5% 时两条线都没有可分辨的精度下降（IMU_RGBD 反而略低，属种子波动）；r = 10% 时 IMU_RGBD 开始明显变差，纯 RGBD 的表面 ATE 不可用，只能看覆盖率（0.921）和 final（0.166）。

### 6.4 整帧深度中断

- **中断窗口内跟踪没有断**：easy 全部 18 次运行（2 模式 × 3 档 × 3 种子）在窗口 `[10 s, 10+时长)` 内的有效帧比例都是 1.000（5/5、10/10、20/20 帧）；窗口结束后才计的恢复时间因此都是 0.0 s。这是"RGB 一直在、ORB-SLAM3 用 RGB 继续跟踪"的直接证据，不是出图错误（`03_outage_office_easy_p004.png` 上子图）。
- **easy RGBD 的 1–2 次失跟都不在中断窗口内**：组均 1–2 次（单次 0–4 次；O05 1.67、O10 2.0、O20 1.0），事件起点最早 28.0 s，其余分布在 28.3/28.7、63.7/65.2/67.3、75.7/75.8/76.3、85.6 s（从各运行 `tracking.csv` 逐帧统计；`outage_start_s/outage_end_s` 见 `depth_ablation_runs.csv`），全部晚于窗口结束（≤ 12 s）。所以不能写成"中断导致 1–2 次失跟"；IMU_RGBD 的失跟为 0。
- O05 RGBD 的 ATE 均值 0.187 ± 0.150（种子 1 单次 0.358），是中断实验里最差的一档；但 O10（0.066）和 O20（0.115）都没有跟着变差，0.5 / 1 / 2 s 之间没有单调关系，3 个种子不足以定趋势。只能说短时深度丢失靠 RGB + 惯性可以接住。
- **hard 的窗口内有效帧比例**（`03_outage_office_hard_p004.png` 上子图）：RGBD 为 O05 1.00、O10 1.00、O20 0.833 ± 0.289（种子 0 = 0.50，失跟起于 11.0 s；种子 1/2 为 1.00）；IMU_RGBD 为 O05 0.600 ± 0.529、O10 0.567 ± 0.115、O20 0.117 ± 0.202，部分失跟起点落在 10.0/10.4/10.5/10.7 s。O20 IMU_RGBD 的 0.117 明显低于同批运行的覆盖率 0.615–0.622，说明失跟集中在窗口内；但 hard 无扰动基线本身每次运行就有 IMU_RGBD 148–152 次、RGBD 29–32 次失跟、1–5 次未恢复（本批中断档 IMU_RGBD 146–151 次；恢复时间单次 0–4.8 s、组均 0.07–1.7 s），3 个种子分不开"中断触发"与"基线重置"，只作观察，不作趋势结论。

### 6.5 整条无深度（depth_off）：初始化失败，不会退回单目惯性

- easy 和 hard 各 3 个种子 × 2 种模式，共 12 次全部 `init_failed`，覆盖率 0，没有一次进入正常跟踪。
- 逐帧看 easy RGBD 种子 0（`results/C/runs/office_easy_p004__depth_off_ALL_s0__RGBD/tracking.csv`）：1218 帧里 609 帧状态 OK、609 帧 LOST，交替出现；**所有 609 个 OK 帧的跟踪点数都是 0**（metrics.json 的 `n_ok_but_empty` = 609，有效帧 0）。即每帧建出一个空地图、下一帧就丢掉，再重建，初始化永远凑不够关键帧，直到序列放完（wall 131.7 s ≈ 1218 帧 × 0.1 s）。退出码 0，不是崩溃。
- IMU_RGBD 同样 `init_failed`：ORB-SLAM3 的 RGB-D 惯性模式没有在无深度时回退到单目惯性，这一点实测如此，和"无缝切换"的预期相反。

### 6.6 崩溃（2 次）

- `office_easy_p004__invalid_pixels_P20_s2__RGBD`：t = 114.2 s，exit 134（SIGABRT）。
- `office_easy_p004__invalid_pixels_P80_s2__RGBD`：t = 111.7 s，exit 134。
- 两次都是同一条：Sophus `SO3::exp` 的 ensure 失败，omega 为 NaN（`results/C/runs/.../run.log`）。崩溃前的帧照常参与评测（汇总里 P20/P80 的 ATE 是 3 个种子的值），这两次没有 final 指标。
- 12 次 depth_off 运行和 IMU_RGBD 的对应档位都没有崩溃。

### 6.7 回环

- easy 上回环很常见：RGBD 23/34 次成功运行（status=ok）有 ≥1 次回环，IMU_RGBD 10/36，IMU_MONOCULAR 1/3；hard 全部 0 次（`results/C/depth_ablation_runs.csv` 的 `n_loops`）。
- easy 的 IMU 模式共有 11 次回环运行（IMU_RGBD 10 + IMU_MONOCULAR 1），其中 9 次的 final 被拉大到 6.2–8.0 m（clean IMU_MONOCULAR s0 6.24，P00 IMU_RGBD 7.50 / 7.96 / 7.90，N1 s0/s2 7.76 / 8.02，N2 s0 7.74，O05 s1 8.04，O10 s2 7.36），另 2 次为 0.040（O05_s0）和 0.053 m（N1_s1）；IMU_RGBD 内是 8/10。同一批的在线 ATE 只有 0.024–0.046 m。原因是惯性回环矫正把一段轨迹拉长约 1.37 倍（由轨迹核查确认）。
- 同样是回环，RGBD 的 final 只有 0.07–0.48 m，说明问题在"惯性 + 回环"，不在回环本身。所以本报告 final ATE 一律和是否回环一起给。

### 6.8 P80 RGBD 的 ATE 不可比

`office_easy_p004` P80 RGBD：在线 ATE 0.026 ± 0.004 m，但段数 98.7（P50 为 43，无扰动 16.7）、对齐覆盖率 0.850、覆盖率 0.985；final ATE 0.083 m（n = 2，种子 2 崩溃无 final）。在线与 final 相差 3.2 倍，在线值不能当作"80% 无效深度下更准"的证据。引用这个数时必须同时给出段数、对齐覆盖率和 final ATE。（来源：`results/C/depth_ablation.csv`）

### 6.9 hard：段数暴涨、ATE 反而变小的点

hard 的基线本身在反复重置（无扰动 IMU_RGBD 153.7 段、149.7 次失跟、覆盖率 0.630），因此这里只列数值异常，不解释成故障趋势。按要求排查"段数上升且 ATE 变小"的设置：

1. **invalid_pixels P80 · IMU_RGBD**（`depth_ablation.csv`）：段数 186.7（无扰动 153.7，+21%），其中真正参与 ATE 的段 24.7（无扰动 51.7），对齐覆盖率 0.129（无扰动 0.285），在线 ATE 0.0203 m（无扰动 0.1121，0.18 倍），覆盖率 0.542，未恢复 8.3 次。ATE 变小的直接原因是参与对齐的帧只剩 13%；final 指标因保存崩溃缺失，无法交叉验证。**这是 hard 上最典型的不可比点。**
2. **P50 / P20 / N2 · IMU_RGBD**：段数与基线几乎相同（157.7 / 154.7 / 154.3 对 153.7），但 ATE 为 0.058 / 0.061 / 0.067（0.52–0.60 倍），对齐覆盖率 0.244 / 0.265 / 0.271 对 0.285。段数没涨，ATE 却减半——对齐段变短、被丢弃的帧变多，效果与第 1 点相同，只是没有体现在总段数上。
3. **outage O10 · RGBD**：段数 97.3（无扰动 93.7），对齐覆盖率 0.286（无扰动 0.284），ATE 0.151 对 0.128（升高），不符合本条；列出是为了说明并非所有 hard 设置都出现 ATE 下降。O20 RGBD 则是 ATE 0.0755（0.59 倍）而段数持平，归入第 2 类。

对应的 easy 例子：P80 RGBD（段数 16.7 → 98.7，ATE 0.097 → 0.026）与 N4 RGBD（16.7 → 86.0，0.097 → 0.045），见 6.2 / 6.3。

## 7. 局限

- 只有一个场景（Office）的两条轨迹，结论可能只适用于室内近距离场景。
- 深度退化是对录制数据的离线人工退化，不是真实传感器失效；随机无效像素是逐像素独立的，比真实深度相机的成片空洞更"温和"。
- 图像 10 Hz；hard 的难度来自原始快速运动（角速度最高 3.8 rad/s），不是人工退化。
- 恢复时间的 0.5 m 门限按段对齐，对新段偏宽松（见 3.3）。
- 每个设置只有 3 个种子；单条轨迹上的上千帧不算独立重复。
- **在线 ATE 与段数强耦合**：按段各自对齐时，段越短、参与 ATE 的帧越少，ATE 越乐观。本报告一律同时给段数、对齐覆盖率和 final ATE，但 P80/N4 这类"ATE 变小"仍无法还原成整条轨迹的误差；不要把这类 ATE 横向比较。
- **hard 的 IMU 模式没有 final 指标**：保存时 `Map 0 has 0 KFs` 导致段错误（wait_status=139），`trajectory_est.tum` 为空。这是 ORB-SLAM3 在反复重置后保存空地图的问题，不是评测端丢弃。
- **hard 的基线本身失败**：无扰动 IMU_RGBD 已 153.7 段、149.7 次失跟、4.7 次未恢复、覆盖率 0.630；在此基础上，故障档位之间的差异和基线重置混在一起，不能归因于深度退化。hard 只用于"两条轨迹"的完整性，趋势以 easy 为准。
- **两处疑似漏检**：hard MONOCULAR t≈56.8 s、hard depth_noise_N3 RGBD t≈26.1 s 可能还有未检出的世界系变化；这两处的段可能被错并，ATE 偏大。未在 metrics 里单独标记。
- **崩溃前的帧计入 ATE**：P20/P80 RGBD 的 ATE 均值包含种子 2 崩溃前的轨迹（`ate_online_rmse_n` = 3），与"完整跑完"的均值不完全同质；final ATE 则只有 2 个种子。
- **depth_off 的原始 tracking.csv 会出现 state=OK**：空地图上 ORB-SLAM3 报 OK 但跟踪点数为 0，评测端按"≥1 点"判为无效；直接读 tracking.csv 时应以 quality_rgb ≥ 1 为准。
- **中断指标的口径**（见 3.3）：恢复时间要求新段按自身对齐、0.5 m 门限对刚重置的段容易满足；easy 上 18 次中断窗口内有效帧比例全为 1.000、窗口后恢复时间全为 0.0 s，说明跟踪根本没有中断，恢复时间在 easy 上没有信息量，故图里改用窗口内有效帧比例。hard 上恢复时间 0–4.8 s、未恢复数包含与中断无关的基线重置，且窗口内比例与整次运行覆盖率接近（IMU_RGBD 基线约 0.62），不能据此单独归因。
